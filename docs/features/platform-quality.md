Related: [ADR-011](../decisions/011-oauth-tokens-encrypt-at-rest-via-a.md), [ADR-012](../decisions/012-date-only-values-are-utc-midnight-calendar.md), [ADR-016](../decisions/016-postgres-migration-baseline-prisma-migrate-replaces-db.md), [ADR-022](../decisions/022-security-header-baseline-no-csp-yet-and.md), [ADR-035](../decisions/035-statute-periods-are-calendar-amount-unit-computed.md), [ADR-036](../decisions/036-money-is-decimal-14-2-one-settlement.md), [UI_PATTERNS.md](../UI_PATTERNS.md)

## Shipped
- [x] **Server-side email validation** (F987) — every typed-in email (contacts, parties, new attendees, the new-matter inline client, portal invites) is checked on the server by the one lenient helper `isLenientEmail` (`src/lib/email-shape.ts`); edits never re-reject an unchanged stored value.
- [x] **Date format sweep** (2026-07-07, P2) — every display callsite funnels through `formatDate` / `formatRelative` variants; dashboard queries take the viewer's TZ; date-only inputs parse via `parseDateOnly` (UTC-midnight calendar date) and `parseWallClock` (a wall-clock instant in the user's zone), ADR-012. The old `parseLocalDate` / `parseLocalDateOrDateTime` helpers no longer exist.
- [x] **Timezone awareness in date inputs** (2026-07-07) — same sweep: date-only strings parse to UTC-midnight and render without TZ override, so "March 15" stays March 15 regardless of viewer/server zones (ADR-012).
- [x] **Status / priority / role values as shared constants** (2026-07-07) — `src/lib/constants/` is the canonical client-safe home: per-domain files (task-status, priority, deadline-status incl. kinds, time-entry-status incl. WIP subset, lead-stage incl. open/closed partitions, invoice-status incl. kinds, calendar-event-type, settlement-status) export `as const` arrays + union types + label maps, smoke-tested for drift (`constants.test.ts`). Older homes re-export from there (`note-constants.ts`, `queries/leads.ts`, `billing-form.ts` with typed transition maps). Server actions and queries migrated (billing WIP predicate, reports pipeline stages derived from `LEAD_OPEN_STAGES`, sidebar/palette/leads closed-stage filters). Matter itself has no status column (stage is a DB-backed FK), so no matter-status constant.
- [x] **Shared `<EmptyState>`** (2026-07-07) — `src/components/shared/empty-state.tsx` (icon + title + optional description + CTA slot + `framed` dashed variant; see UI_PATTERNS.md); adopted at about 14 sites (search page, template library, notifications feed, matter tasks/deadlines/events tabs, contacts directory, intake queue, matters table, email thread list).
- [x] **Pluralization** (2026-07-07) — `plural(n, "matter")` + `pluralize(noun)` in `src/lib/utils.ts` (regular rules, -es/-ies, irregulars map, explicit-plural override). Fixed matters-toolbar "1 matters" and the thread-list/reader counts.
- [x] **PracticeArea color vs Matter color drift** — a matter still snapshots the area color on create, but recoloring an area now recolors matters still on the OLD color; per-matter overrides are preserved (`updatePracticeArea`).
- [x] **Email label formatting** (2026-07-07) — `formatEmailLabel` in `src/lib/format-label.ts` (strips `custom:` and redundant `_label`, splits snake/kebab, title-cases) used by thread-reader chips; the inbox deadline-kind select uses `DEADLINE_KIND_LABEL`.
- [x] **HTML sanitization audit** (2026-07-07, updated 2026-10-16) — no stored-XSS gap. `matter.description` renders as React-escaped text, never `dangerouslySetInnerHTML`. Every `dangerouslySetInnerHTML` in src/ renders `Note.content` only, and every `Note.content` write path sanitizes at the boundary: `sanitizeUserHtml` (`src/lib/sanitize-html.ts`; library is `sanitize-html`, not DOMPurify) in notes / captures / inbox-actions, entity-escaping `textareaToHtml` in `note-on-entity.ts`. ADR-022: sanitizer profiles allow NO `class` (only `span.email-blocked-image` in the email profile) and protocol-relative hrefs are rejected. Pre-existing `Note.content` / `EmailMessage.body` rows are re-sanitized at read time (`matter-detail/notes.ts`, `calendar.ts`, `thread-reader.tsx`), so no backfill is needed.
- [x] **`NoteRead` growth** (verified 2026-07-07) — `deleteNote` is a hard delete (no soft-delete path) and `NoteRead`, `NoteReaction` and `parentNoteId` carry `onDelete: Cascade`. Proven by the "deleteNote - hard delete cascades reads + reactions" suite in `src/app/actions/notes.test.ts`. Only nice-to-have: periodic cleanup of reads on very old notes if row counts ever matter.
- [x] **Data-loss hardening (W7)** — contact merge keeps the retired contact's conflict flag, notes and duplicate party-row details (refuses rather than truncating over-long notes); re-adding a party already on the matter in the same category is refused instead of wiping role/notes/representation; the phone manager dialog reseeds from current phones on every open; the create dock keeps each panel's draft; the Parties-tab edit form no longer nulls a legacy `Contact.phone` or duplicates a linked attorney, and changing the shared Contact there needs `contacts.edit`; `prisma/seed.ts` refuses non-local databases (`ALLOW_SEED=1` to override) and ships no fixed password; contact, party and practice-area/stage mutations are audit-logged.
- [x] **Email token encryption at rest** — `EmailAccount.accessToken` / `refreshToken` encrypt with AES-256-GCM via a Prisma query extension on the singleton client; key `EMAIL_TOKEN_KEY` (base64 32 bytes, per environment); versioned wire format `v1:<iv>:<tag>:<ciphertext>` for rotation (ADR-011). Files: `src/lib/email-token-crypto.ts`, `src/lib/email-token-encryption.ts`.
- [x] **Database: production Postgres** — `prisma/schema.prisma` provider is `postgresql`; production runs on Prisma Postgres via the Vercel Marketplace integration (injects `DATABASE_URL`); local dev uses a separate Prisma Postgres `lawcrm-dev` (`DEVDB_DATABASE_URL` on the Development env, see README). Schema changes ship as migrations since 2026-10-16 (ADR-016). Build runs `prisma generate && next build` + `postinstall: prisma generate`. Tests run against a local Docker container (`docker-compose.test.yml`); integration setup waits for the DB, pushes the schema, and `resetDb()` gives each test fresh state in `beforeEach`.
- [x] **Quality sweep Batch 4** (ADR-035 to ADR-038, non-money parts) — calendar-correct SOL periods (amount + unit; also the automations deadline-rule month/year offsets); nine hot-path indexes; `Firm.matterVisibility` column (enforcement later built as ADR-039); `billing.view` read permission (ADR-038); per-event Private calendar events (ADR-037). Money columns `DECIMAL(14,2)` and one-settlement-per-matter are covered in [time-and-billing.md](time-and-billing.md). One migration, `20261017120000_quality_sweep`; run steps in `docs/DEPLOY_BACKFILLS.md`.
