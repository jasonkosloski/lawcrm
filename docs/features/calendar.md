# Calendar

Week / Month / Day views with deadlines, events (create / edit / delete / drag-reschedule), a per-event visibility model, and auto-attendee defaults. Two-way Google sync is in [google-calendar-sync.md](google-calendar-sync.md). Recurrence and viewing another user's calendar are not built.
Related: [ADR-021](../decisions/021-matter-tabs-honour-calendar-visibility-and-money.md), [ADR-037](../decisions/037-private-calendar-events-show-to-their-creator.md), [ADR-012](../decisions/012-date-only-values-are-utc-midnight-calendar.md), [PERMISSIONS.md](../PERMISSIONS.md)

## Open work
- [ ] **Calendar — recurring events** (P1) — Needs an RRULE data-model decision first (series row vs. materialized occurrences, exception handling; schema change). Explicitly out of scope until that ADR lands. Until then Google sync imports recurring instances individually (`singleEvents=true`).
- [ ] **Calendar — visibility v2** (P2) — A user can opt to view another user's calendar, with the visibility resolver still in force (they see only what they'd see anyway). Foundation in place.
- [ ] **Real RSVP statuses** (P2) — Remaining from event-create v2.
- [ ] **Day-view chip enrichment** (P2) — Any day-specific enrichment beyond what full width already gives. Also: matter reassignment of an existing event is not supported anywhere.

## Shipped
- [x] **Week view** — 7 day columns, hour grid 6am–9pm, events positioned by start/end, deadlines as thin bars, "now" line in today's column, events colored by matter.
- [x] **Month view** — 6-row grid; compact pills (time + title); deadlines styled by kind; "+N more" overflow; today highlighted.
- [x] **Navigation** — Prev/Today/Next, URL-driven (`?view=week|month|day&d=YYYY-MM-DD&show=...`) via `parseCalendarParams` / `buildCalendarHref`; `stepCalendarFocal` centralizes ±1 day / ±7 days / ±1 month.
- [x] **Day view** (2026-07-07) — `?view=day`; `calendarDayInTz` computes the fetch range in the viewer's TZ (DST-safe 23h/25h days). Reuses week-view primitives at full width (`WeekAllDayCell` still a drop target, `WeekTimeColumn` with drag-to-reschedule + edge-resize via `useEventMoves`) plus a deadlines section with full pills (title + matter + critical tag). Week-view day headers and month day numbers deep-link into the day.
- [x] **Deadlines-only filter** (2026-07-07) — `?show=deadlines` ("All | Deadlines" segmented control; default `all` dropped from URL; nav arrows, view switcher and week-header deep-links carry it). One fetch; `filterCalendarItems` filters at render. Month omits event pills; week collapses grid + all-day strip into one tall per-day "due" strip (critical-first, empty state); day shows only the "due" section with explicit empty state.
- [x] **Event create v2** (2026-07-07) — Full-page `/calendar/events/new` (`NewEventForm`): title, type, start–end, all-day (reseed-on-toggle), location, video URL (http(s) only), description, searchable optional MATTER picker (open matters, pinned first; matterless = personal event), shared attendee picker (`components/calendar/attendee-picker.tsx`: users + contacts + new-contact autocomplete), visibility toggle. `createCalendarEvent` (`events.create`) accepts optional `attendees` JSON; creator auto-added as firm attendee; effective `autoAddTeamToNewEvents` pulls the matter team in. Lands on `/calendar?event=<id>`. Toolbar "New event" navigates to the page; a secondary zap button keeps the docked `NewEventComposer` (matterless/personal quick path). Create entry points hide without `events.create`. Matter events write ActivityLog on create/update/reschedule/delete (personal events deliberately unlogged). Google-imported attendee-less events adopt the editor as attendee on first edit.
- [x] **Edit / delete / drag-and-drop** — Edit and delete are INLINE in the event detail modal (delete confirms, failures surface in modal); the old `/calendar/events/[eventId]/edit` route was removed. All-day toggle (datetime ↔ date). Typed attendee picker. Drag-and-drop reschedule: week-view chips to time slots, preserves duration when timed, default 2h when promoting from all-day; Busy chips are non-draggable. Generic DnD utilities at `src/lib/dnd/` (will feed kanban). `moveCalendarEvent` gated `events.edit`.
- [x] **Visibility model** — Per-event + per-user resolver, default-deny with five unlock paths (creator, attendee, matter team, per-event override, creator's user-default). Server-side strip (`getCalendarItems` + `getCalendarEventById` scrub title/location/description/zoomUrl/matter/attendees; neutral color when locked). `events.edit_non_matter` gates editing others' personal events. Invariant: every event keeps ≥1 firm-user attendee (creator fallback). Per-user "Default event visibility" `show_details` (radio on `/settings/profile`) is retroactive for ALL of the creator's events; a per-event **Private event** value (ADR-037; toggle on edit modal, `NewEventComposer`, matter EventComposer) overrides it: creator-only details, Busy for everyone else including invitees and matter team, title kept out of the matter activity log, pushed to Google as a private event. Matter Events tab and Timeline honor this (ADR-021).
- [x] **Auto-attendee defaults** — `Firm.autoAddTeamToNewEvents` + per-matter override: new matter events pull the matter team in as accepted attendees. Adding a team member optionally fans them across upcoming matter events (past untouched). `src/lib/calendar-default-attendees.ts`.
