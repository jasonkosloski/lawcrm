# Communication — Phone, SMS, Voicemail

Manual call logging, edit/delete, missed-call flags, and the matter-detail Phone channel are shipped. Everything is stored as `MessengerItem` rows in `MessengerThread`s and rendered inline in the Messages view at `/communication`. Provider-driven SMS and voicemail are not built (need a provider). Email lives in [communication-email.md](communication-email.md).
Related: [PERMISSIONS.md](../PERMISSIONS.md)

## Shipped

- [x] **Text from template** — beside "Log call" on matter and lead Communication tabs (same `communication.log_call` gate): pick a text template and a record contact with a phone, see the filled text with its character / segment count, then **Copy** (send from your phone) or **Copy and log**, which records an outbound text on the contact's thread via `logText` (`src/app/actions/calls.ts`; same thread rules as `logCall`; the contact must be one of the record's own contacts; filed to the matter, while a lead's text logs against the lead — so the lead's wall covers it — and stays unfiled on the thread, like lead calls). The dialog starts fresh each time it opens.

- [x] **Manual call logging v1** — "Log call" button in the Messages thread-list header. Composer: contact typeahead (auto-fills phone; editable / required when none on file), direction, outcome (answered/missed/no answer), date-time (read in the user's profile zone), duration (answered only), optional matter + summary. A number already on another contact is blocked. Action `logCall` (`communication.log_call`) writes a `kind="call"` `MessengerItem` (providerEventId `manual-<uuid>`) into the contact's thread, reusing the firm's first active MessengerAccount or bootstrapping a `provider="manual"` one; normalizes phone to E.164, backfills `thread.contactId`, advances `lastItemAt` without regressing. Summaries render under the call chip in the reader. Activity-log type `"call"` (Phone icon; included in Timeline "Communications" filter).
- [x] **Call log edit / delete** — Kebab on manually logged items (thread reader + matter Phone channel), gated `communication.edit_call` / `communication.delete_call`; manual items detected by the `manual-` providerEventId prefix (`MessengerItemRow.isManual`). Edit reuses `CallLogDialog` prefilled (outcome, direction, when, duration, summary, matter re-file); contact + phone fixed (thread identity). `updateCallLog` / `deleteCallLog` refuse provider-synced items, recompute `thread.lastItemAt`, delete the thread when its last item goes (re-created on demand by (account, phone)). Spawned time entries / tasks / notes survive a delete with FK nulled. "Log call" also appears on the lead Communication tab (lead's contact pre-selected, no matter — conversion creates it; a thread default matter can still route it) and on the contact page (contact fixed via `fixedContact`).
- [x] **Matter-detail Phone channel** — Email | Phone toggle on the matter Communication tab (`?channel=phone`). Lists every call / text / voicemail filed to the matter (directly or via thread default routing — `listMessengerItemsForMatter`), newest first, linking to the full reader. Hosts the Log-call composer with the matter pre-selected (no picker); matter's client + parties float to the top of the contact typeahead.
- [x] **Missed-call detection** — Thread rows flag missed calls from raw `MessengerItem.callStatus` (`lastCallStatus` on `MessengerThreadRow`) via shared `isMissedCall` (inbound + missed/no_answer/declined; busy/failed render neutrally), replacing the old `lastBody === "Missed call"` heuristic.
- [x] **Thread read tracking** — shared with email; see [communication-email.md](communication-email.md) (`markMessengerThreadRead` + `unreadCount`).
