# Documents

Per-matter document file system (folders, multi-file upload, in-page viewer for most file types), the firm template library (structured templates, blocks, .docx generation), and driver-based storage (local disk in dev, private Vercel Blob in prod). Evidence review (flags on documents) is in [evidence-review.md](evidence-review.md). Intake documents reuse the same models: see [ADR-046](../decisions/046-intake-documents-share-document-and-documentfolder-scoped.md). Records-request responsive documents: see [ADR-047](../decisions/047-records-requests-are-a-dedicated-model-with.md).
Related: [ADR-015](../decisions/015-driver-based-document-storage-local-disk-in.md), [ADR-018](../decisions/018-private-blob-store-presigned-urls-for-documents.md), [ADR-034](../decisions/034-document-bytes-never-travel-through-server-actions.md), [ADR-041](../decisions/041-pdfs-render-in-the-page-with-pdf.md), [ADR-042](../decisions/042-excel-and-email-convert-on-the-server.md), [ADR-043](../decisions/043-email-attachments-become-documents-copy-to-makes.md), [PERMISSIONS.md](../PERMISSIONS.md)

## Shipped

- [x] **Text styles** (2026-10-22) — [ADR-067](../decisions/067-text-styles-are-firm-json-resolved-once.md). Firm-wide named paragraph styles, independent (each spells out every value), edited in Settings → Documents → Styles: eight built-ins (Body, Title, Heading 1–3, Caption, Block quote, Signature; renamable, not deletable) plus custom ones; delete is refused while a template or block uses the style. Stored as JSON (`DocumentStyle.paragraphStyles`, NULL until first saved = defaults derived from the house style); Body owns text size and spacing. A paragraph picks a style and may carry direct settings (spacing, line spacing, indents, first line, flow, alignment; explicit 0/false/none are kept); text carries bold, italic, underline, small caps, all caps and size marks. One resolver (paragraph, then court override, then firm style) runs in `renderTemplate`; Word, PDF and the preview read `attrs.resolved`. Word gets real styles (Normal, Title, Heading 1–3 under Word's built-in names, so a rename of those isn't visible in Word); the PDF's keep-with-next is an approximation; preview HTML carries resolved inline styles under a strict sanitizer allowlist. Sent emails carry template paragraph styles through the strict outgoing allowlist (`sanitizeOutgoingEmailHtml`, Email editor preset; see communication-email). Template headings are paragraphs with heading1–3 styles (old heading nodes convert on open and render). The editor draws real styles and has a Style menu, Paragraph popover, All caps, size box and Clear formatting. Unknown style keys render as Body and warn; they never block a save. A court format overrides individual values of individual styles (Court formats → Styles); its size/line spacing/space after live in the Body row, and each save mirrors them into the legacy `CourtFormat` columns, which are still overlaid on read until the drop migration. The legacy house columns are still read while `paragraphStyles` is NULL (defaults derive from them); the drop migration must backfill `paragraphStyles` first. Follow-ups under Open work.
- [x] **Transcripts for audio/video** (2026-10-21) — [ADR-062](../decisions/062-transcription-runs-at-a-provider-on-request.md). One `Transcript` per Document with speaker-turn `TranscriptSegment`s (word timings in `words`; `text` derived from them). On request only (`documents.transcribe`): the file goes to AssemblyAI, a webhook finishes the job and a sweep cron covers missed webhooks, timeouts and provider-copy purges. A failed re-run keeps the previous text; without a provider key Transcribe is disabled. A "Copy to…" copy reuses a completed transcript free (not counted against the monthly hour cap). With transcript text the viewer is transcript-first (player, "Flag this moment" and flags in a side column): synced active word, follow mode, click-to-seek, find, speaker chips; select text to **Flag selection** or **Copy with timecode**. Corrections (`documents.transcript.edit`): edit a paragraph (optimistic `revision` conflict with "Use theirs" / "Keep mine and save"), reassign or rename speakers, show/revert the original, and **Change speaker** on any selected run. Global-search type (hits open at `?t=`, see [search.md](search.md)). Export: `/print/transcripts/<documentId>` (browser Save-as-PDF). Not in the client portal.
- [x] **Caption tables** (2026-10-22) — [ADR-066](../decisions/066-template-tables-split-into-rows-and-columns.md). Template tables are built for court captions: full width (margin to margin, the default) or fit to content; drag-to-resize columns, kept as proportions in full-width tables; a typed column width in inches (Width popover: exact in fit tables; in full-width tables the other columns share the rest of the text width at the house margins, so a court format with other margins scales it); merge and split cells across columns and down rows (a pinwheel of merges the PDF can't lay out is refused); per-side borders (none, thin, thick) with all/outside/inside/none presets that keep neighbouring cells in step; vertical alignment (top, middle, bottom) and the usual horizontal alignment on every selected cell. A "Table" menu adds and deletes rows and columns. Word, PDF and the preview share one layout (`src/lib/templates/table-layout.ts`). The PDF prints ☐ ☑ ☒ and check marks through a DejaVu Sans fallback. Small caps is a text format beside bold/italic/underline (Ctrl/Cmd+Shift+K): Word uses its own, the preview CSS `font-variant`, the PDF lowercase as capitals at 80% size. Follow-ups: borders and small caps in emailed tables.
- [x] **Court formats** (2026-10-22) — [ADR-065](../decisions/065-court-formats-override-blocks.md). Firm-defined `CourtFormat` (Settings → Court formats): optional overrides on the house style (font, margins, page numbers, and per-style values such as Body's size and spacing), paper size Letter or Legal, and block replacements. A venue picks a format and carries a caption name; `matter.courtCaption` feeds the caption. Filings for a matter whose venue has an active format use it in Word, PDF and previews; letters never do. Replacements apply to blocks the template inserts; filings have no letterhead or continuation header. An archived format is ignored with a note. The template editor's "Preview as" shows a template under a format. Gated by `court_formats.add/edit/delete`. Follow-ups: pleading paper / line numbers; per-court template variants if ever needed; shipped court-rule libraries; a stale guard for format edits between preview and save; one shared court row mapper (`editor-data.ts` / `court-context.ts`).
- [x] **Letters out** (2026-10-22, P1) — [ADR-064](../decisions/064-letters-render-twice-from-one-style.md). Firm house style at `/settings/documents` (one `DocumentStyle` row per firm; edit needs `firm.edit_document_style`, read-only otherwise): font, size, line spacing, space after, four margins, letterhead block, logo (position, upload, remove), continuation-header block (seeded default: client name · date) and page numbers, with a live page-shaped sample. `resolvePageStyle` turns it into one `PageStyle` (letter or filing) feeding two converters over the same `ResolvedDoc`: `.docx` (`to-docx`) and PDF (`to-pdf.tsx`, `@react-pdf`), with bundled metric-compatible fonts (Garamond's line breaks may differ slightly). Letterhead is the first-page header and the continuation block the later-page header; page 1 is never numbered (letters print "Page N" in that header, filings in the footer). The PDF and preview copy Word's layout so page breaks match. Logo upload (`POST /api/document-style/logo`, ADR-034) takes PNG or JPEG up to 1 MB, is stale-checked like Save; a missing or corrupt logo renders without it and is reported. Deleting a block the style uses is refused.
- [x] **Templates foundation** (2026-10-22, P1) — [ADR-063](../decisions/063-templates-are-structured-documents.md). Firm library at `/settings/templates` (tabs Templates and Blocks), visible to everyone; manage affordances behind `documents.template.create/edit/delete` (blocks use the same keys; archive under edit, delete refused while a template references the block). Each template has a `kind` (letter, email, sms, filing) and `appliesTo` (matter, lead, both). Content is TipTap JSON (`src/lib/templates/`): prose, tables, page breaks, plus field chips with formats, firm-editable blocks, Show-if sections, Repeat-for-each lists and list fields; the zod schema validates every save. Full-page editors (desktop only; read-only preview on small screens) preview live against sample data or a real record and warn on unknown, out-of-scope or archived items. Legacy `{{token}}` bodies convert on open or on generation; saving writes `content`. The pure `renderTemplate` never goes silent: missing data renders a marked `[… — not on file]` run and is reported. Generate from template on the matter and lead Documents tabs: pick a fitting active letter/filing template, a signer (team member, defaults to you) and a recipient (record contact, when used), preview, then Copy text or Save as Word, PDF or Both (`<template> — <date>.docx` / `.pdf`, `source: "generated"`; needs `documents.upload`). Save re-renders on the server, refuses if the template changed since the preview, and is all-or-nothing; warnings (unknown fields, an unusable logo or font) appear after save. Records-request letters use the same engine with `request.*` and `custodian.*` fields.
- [x] **Matter detail: Documents tab** (2026-07-07) — per-matter document file system.
  - Folders: left-rail collapsible tree (`DocumentFolder`, nesting capped at 8 levels, per-folder direct-count badges, "All documents" = matter root); URL-driven selection `?folder=<id>` (unknown ids fall back to root); breadcrumbs. The browser lists the folder's subfolders + files (name/category/status/size/uploader/date); names link to the viewer.
  - File-manager interaction (2026-10-21, Drive/Dropbox-style): `documents-browser.tsx` (server) shapes rows; `documents-workspace.tsx` (client) owns multi-select, the selection bar, right-click menus, drag-to-move (drop rule `moveBlockReason` in `src/lib/document-selection.ts` mirrors the server's refusals; every move toasts Undo), desktop drop-to-upload and keyboard shortcuts. One pure action list (`src/lib/document-entry-actions.ts`) feeds kebab, menu, bar and shortcuts so they can't drift. Bulk work calls the per-item actions so every guard still runs.
  - Write gates: New folder `documents.folder.create`; rename `documents.folder.edit`; delete `documents.folder.delete` (contents re-parent up a level with " (2)"-style collision suffixes; files are NEVER deleted with a folder); Move to… on files and folders `documents.organize` (shared picker, cycle-proof disabled targets). Tree math is the pure tested `src/lib/folder-tree.ts`.
  - Upload: multi-file uploader into the current folder via XHR (progress events) against streaming `POST /api/documents/upload`, per-batch progress + cancel, client pre-flight of size caps (100 MiB standard / ~2 GiB media), all-or-nothing batches. The single-file composer (display-name override + category) uses the same transport (no 1 MB limit). Download per row (`?download=1` forces attachment). Delete: original uploader or `documents.delete_any`; refused while other reviewers' evidence flags exist unless the user holds `evidence.flag.delete_any`. "Generate from template" kept.
  - Limit: NO edit-metadata action (no rename or re-categorize after upload).
  - Downloads are gated end-to-end by `/api/documents/[id]/download` (streams local files; 302s to a presigned blob URL otherwise).
- [x] **Document viewer v1** (2026-07, extended 2026-10-18) — full-page inline viewer at `/matters/[id]/documents/[documentId]`. Renderer choice is the pure tested `resolveDocumentRenderer` (contentType first, extension fallback for typeless scans).
  - **PDF**: built-in pdf.js viewer (ADR-041): canvas + selectable text layer, only pages near the viewport rendered (multi-thousand-page productions stay fast), page jump/prev/next, zoom that keeps your place; password-protected or unreadable files fall back to a download card. Typeless `.pdf` uploads preview too.
  - **Images** png/jpg/gif/webp (click-to-zoom 1:1); **TIFF** (multi-page, decoded in a Web Worker with timeout, up to 300 pages); **iPhone HEIC/HEIF** (converted to JPEG in the browser).
  - **Video** mp4/webm/mov (`preload="metadata"` + Range streaming so GB-scale bodycam seeks without full download); **audio** mp3/m4a/wav/ogg (wide-timeline card, 1x/1.25x/1.5x/2x rate control).
  - **Word .docx**: client-side docx-preview render, then a post-render sanitation walker (`sanitize-rendered-docx.ts`: dangerous hrefs, scripts/embeds, remote images and external CSS removed; `renderAltChunks` off). Fallback: server-side mammoth + `sanitizeDocumentHtml` (5 MB cap), precomputed on every docx view so a parse failure swaps instantly (that HTML rides the RSC payload). Known gaps: approximate embedded-font metrics, poor floating objects/text boxes, layout-driven page breaks, unresolved TOC fields.
  - **Text/CSV** (1 MB read cap; CSV becomes a table when it parses cleanly, else escaped `<pre>`).
  - **Excel .xlsx** (ADR-042): every sheet as a values-only table with column letters + row numbers, capped 2,000 rows x 60 columns x 25 sheets with a notice.
  - **Email .eml / Outlook .msg** (ADR-042): headers, attachment names + sizes, body through the hostile-mail sanitizer (scripts stripped, remote tracking images blocked); `cid:` inline images render as data: URIs and are not double-listed as attachments. xlsx and email are server-converted, so select-to-flag quote tagging works like Word.
  - Everything else (legacy .xls, .pptx, zip, legacy .doc, unknown) gets a download card; any conversion/read failure degrades to an error card, never a 500.
  - **Email attachments + multi-folder filing** (2026-10-18, ADR-043): uploading an .eml/.msg adds each attachment as its own document nested under the email; older emails get "Add attachments to documents". "Copy to…" (row menu + viewer header) makes an independent copy in another folder (own name, flags, notes) without re-uploading bytes; deleting an email keeps attachments copied elsewhere and asks about the rest.
  - **File tree rail** (2026-10-18, desktop widths): the matter's folders and files, current file's folder chain open and highlighted, filter by name, big folders show 200 files then "Show all", matters over 3,000 files list only the current folder and link other folders to the Documents tab (`getViewerFileTree`); collapsible, remembered per browser.
  - Chrome: breadcrumb back to Documents preserving `?folder=`, category/status chips, size + uploader + date, Download, prev/next through the folder ordered by name (server-resolved).
- [x] **Document storage: production Vercel Blob** (2026-07-07, ADR-015; private since 2026-10-16, ADR-018) — `src/lib/file-storage.ts` is a facade over `local` (`./uploads/`, dev default) and `vercel-blob` drivers (`src/lib/storage/`); `BLOB_READ_WRITE_TOKEN` selects blob, `STORAGE_DRIVER` overrides. One key scheme (`{rand16}__{name}`) everywhere; blob rows store the full blob URL in `Document.fileUrl`; reads/deletes dispatch on key shape so driver switches never strand old rows. Prod uploads are client-direct (`/api/documents/upload/blob`: `handleUpload` token route checks session + `documents.upload` + matter/folder scoping + extension-derived allowed types/size caps; Vercel's signed callback creates the Document row); bytes never transit our functions (ADR-034, clears the ~4.5 MB serverless body cap). The busboy streaming route stays for local dev (blob's callback cannot reach localhost) and 501s under the blob driver. Documents and cached email attachments live in a PRIVATE store: a stored URL fetches nothing (403); download routes 302 to a presigned GET scoped to one file (15 min; 6 h for audio/video so long recordings keep seeking). Server-side reads (docx/text/CSV previews, filing an attachment to a matter) use an authenticated `get()` via `readStoredFile`.
- [x] **Document metadata edit** (rename, re-categorize after upload) — `documents.edit` (migration-granted to roles holding `documents.upload`). `updateDocumentMetadata` in `src/app/actions/documents.ts`: wall via `assertChildMatterAccess`, name trimmed 1-255, category from `DOCUMENT_CATEGORIES`, no-op when unchanged, one activity row ("Renamed document" / "Changed document category" / "Edited document details"). "Edit details" dialog (`edit-document-dialog.tsx`) from the row kebab and the viewer header; metadata only, never bytes (ADR-034).
