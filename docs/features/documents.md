# Documents

Per-matter document file system (folders, multi-file upload, in-page viewer for most file types), the firm template library with merge fields, and driver-based storage (local disk in dev, private Vercel Blob in prod). Evidence review (flags on documents) is in [evidence-review.md](evidence-review.md). Intake documents reuse the same models: see [ADR-046](../decisions/046-intake-documents-share-document-and-documentfolder-scoped.md). Records-request responsive documents: see [ADR-047](../decisions/047-records-requests-are-a-dedicated-model-with.md).
Related: [ADR-015](../decisions/015-driver-based-document-storage-local-disk-in.md), [ADR-018](../decisions/018-private-blob-store-presigned-urls-for-documents.md), [ADR-034](../decisions/034-document-bytes-never-travel-through-server-actions.md), [ADR-041](../decisions/041-pdfs-render-in-the-page-with-pdf.md), [ADR-042](../decisions/042-excel-and-email-convert-on-the-server.md), [ADR-043](../decisions/043-email-attachments-become-documents-copy-to-makes.md), [PERMISSIONS.md](../PERMISSIONS.md)

## Shipped
- [x] **Transcripts for audio/video** (2026-10-21) — [ADR-062](../decisions/062-transcription-runs-at-a-provider-on-request.md). One `Transcript` per Document with speaker-turn `TranscriptSegment`s (word timings in `words`; `text` derived from them). On request only (`documents.transcribe`): `requestTranscript` presigns the file to AssemblyAI (dev uploads bytes from the server), `/api/webhooks/assemblyai` (per-job secret, re-fetches the result) finishes the job, and the `/api/transcription-sweep` cron (every 10 min) covers missed webhooks, 6 h timeouts and retrying provider-copy purges (`transcript_purges`, fed by a BEFORE DELETE trigger so failure, timeout and mid-flight document deletes also remove the provider copy). Re-run over a corrected transcript asks first; a failed re-run keeps the previous text under a failure banner. A "Copy to…" copy reuses a completed transcript (free, checked before the cap and not counted); otherwise the monthly hour cap applies. Viewer pane (`src/components/transcripts/`): synced active word, follow mode with a "Resume following" pill, click-to-seek, find bar, speaker chips with timecodes, polls every 15 s while a job runs. Select text to **Flag selection** (span flag with the quote; flags tint the covered words) or **Copy with timecode** (`"…" (doc at m:ss)`, h:mm:ss over an hour). Corrections (`documents.transcript.edit`): edit a paragraph (words re-aligned, timings interpolated, optimistic `revision` conflict), reassign speaker, rename a speaker everywhere, show/revert the original. Transcripts are a global-search type (hits open the viewer at `?t=`, see [search.md](search.md)). Export: chrome-free `/print/transcripts/<documentId>` (browser Save-as-PDF) with a corrected/uncorrected notice. Not shown in the client portal. Key files: `src/lib/transcription/`, `src/app/actions/transcripts.ts`.
- [x] **Document templates / template library** (2026-07-07, P1) — firm-wide library at `/settings/templates`, visible to everyone; manage affordances behind `documents.template.create/edit/delete`. Templates carry `{{merge.field}}` tokens resolved by `src/lib/template-merge.ts`: typed catalog (matter.*, client.*, firm.*, user.name, today; exported for the editor's insert-field picker), TZ-aware date formatting, never-silent semantics (unknown tokens stay verbatim and are reported as `unresolved`; known fields with no data render "[key — not on file]" and are reported as `missing`). Editor dialog has a live preview against an obviously-fake sample context. Matter Documents tab "Generate from template": pick (active only, grouped by category), preview against the REAL matter context with warnings, then Copy text or Save to documents (the whole dialog, preview included, needs `documents.upload`; hidden without it; writes a `.md` via file-storage, creates a `source: "generated"` Document named "<template> — <date>.md", activity-logged). Archive is a soft `isActive` flip under the edit key; hard delete is separate (delete key). Key files: `src/app/actions/document-templates.ts`, `src/lib/template-merge.ts`.
- [x] **Matter detail: Documents tab** (2026-07-07) — per-matter document file system.
  - Folders: left-rail collapsible tree (`DocumentFolder`, nesting capped at 8 levels, per-folder direct-count badges, "All documents" = matter root); URL-driven selection `?folder=<id>` (unknown ids fall back to root); breadcrumbs. The browser lists the folder's subfolders + files (name/category/status/size/uploader/date); names link to the viewer.
  - File-manager interaction (2026-10-21, Drive/Dropbox-style): `documents-browser.tsx` (server) shapes rows; `documents-workspace.tsx` (client) owns the interaction. Multi-select (click, ⌘/Ctrl-click, shift-range, checkboxes, ⌘A) with a selection bar (download, move, copy, share, delete). Right-click on rows, empty space and tree folders. One pure action list (`src/lib/document-entry-actions.ts`) feeds the ⋯ kebab, right-click menu, bar and shortcuts so they can't drift. Drag rows onto a folder row, tree folder (collapsed ones spring open) or breadcrumb to move; the drop rule is `moveBlockReason` (`src/lib/document-selection.ts`, mirrors the server's refusals). Every move toasts Undo. Desktop files dropped on the tab upload into the current folder, or onto a folder to upload there. Keyboard: arrows, shift+arrows, space, Enter, F2, Delete, Esc. Bulk work calls the existing per-item actions so every guard still runs; a bulk delete keeps emails' unsaved attachments.
  - Write gates: New folder `documents.folder.create`; rename `documents.folder.edit`; delete `documents.folder.delete` (contents re-parent up a level with " (2)"-style collision suffixes; files are NEVER deleted with a folder); Move to… on files and folders `documents.organize` (shared picker, cycle-proof disabled targets). Tree math is the pure tested `src/lib/folder-tree.ts`.
  - Upload: multi-file uploader into the current folder via XHR (progress events) against streaming `POST /api/documents/upload`, per-batch progress + cancel, client pre-flight of size caps (100 MiB standard / ~2 GiB media), all-or-nothing batches. The single-file composer (display-name override + category) uses the same transport (no 1 MB limit). Download per row (`?download=1` forces attachment). Delete: original uploader or `documents.delete_any`; refused while other reviewers' evidence flags exist unless the user holds `evidence.flag.delete_any`. "Generate from template" kept.
  - Limit: NO edit-metadata action (no rename or re-categorize after upload).
  - Downloads are gated end-to-end by `/api/documents/[id]/download` (streams local files; 302s to a presigned blob URL otherwise).
- [x] **Document viewer v1** (2026-07, extended 2026-10-18) — full-page inline viewer at `/matters/[id]/documents/[documentId]`. Renderer choice is the pure tested `resolveDocumentRenderer` (contentType first, extension fallback for typeless scans).
  - **PDF**: built-in pdf.js viewer (ADR-041): canvas + selectable text layer, only pages near the viewport rendered (multi-thousand-page productions stay fast), page jump/prev/next, zoom that keeps your place; password-protected or unreadable files fall back to a download card. Typeless `.pdf` uploads preview too.
  - **Images** png/jpg/gif/webp (click-to-zoom 1:1); **TIFF** (multi-page, decoded in a Web Worker with timeout, up to 300 pages); **iPhone HEIC/HEIF** (converted to JPEG in the browser).
  - **Video** mp4/webm/mov (`preload="metadata"` + Range streaming so GB-scale bodycam seeks without full download); **audio** mp3/m4a/wav/ogg (wide-timeline card, 1x/1.25x/1.5x/2x rate control).
  - **Word .docx**: client-side docx-preview render (tab stops via `experimental`, table-cell alignment/widths, real page-shaped sections with headers/footers/footnotes), then a post-render sanitation walker (`sanitize-rendered-docx.ts`: javascript:/data:/vbscript: hrefs stripped, http(s) links forced `_blank noopener`, script/iframe/object/embed removed, remote img fetches and external CSS neutralized, `renderAltChunks` off). Fallback: server-side mammoth + `sanitizeDocumentHtml` (5 MB cap `DOCX_MAX_BYTES`), precomputed on every docx view so a docx-preview parse failure swaps instantly (cost: that HTML rides the RSC payload even when unused). Known fidelity gaps: embedded-font metrics approximate, floating objects/text boxes/drawing shapes poor or absent, page breaks layout-driven except where Word saved `lastRenderedPageBreak`, TOC fields do not resolve.
  - **Text/CSV** (1 MB read cap; CSV becomes a table when it parses cleanly, else escaped `<pre>`).
  - **Excel .xlsx** (ADR-042): every sheet as a values-only table with column letters + row numbers, capped 2,000 rows x 60 columns x 25 sheets with a notice.
  - **Email .eml / Outlook .msg** (ADR-042): headers, attachment names + sizes, body through the hostile-mail sanitizer (scripts stripped, remote tracking images blocked); `cid:` inline images render as data: URIs and are not double-listed as attachments. xlsx and email are server-converted, so select-to-flag quote tagging works like Word.
  - Everything else (legacy .xls, .pptx, zip, legacy .doc, unknown) gets a download card; any conversion/read failure degrades to an error card, never a 500.
  - **Email attachments + multi-folder filing** (2026-10-18, ADR-043): uploading an .eml/.msg adds each attachment as its own document nested under the email; older emails get "Add attachments to documents". "Copy to…" (row menu + viewer header) makes an independent copy in another folder (own name, flags, notes) without re-uploading bytes; deleting an email keeps attachments copied elsewhere and asks about the rest.
  - **File tree rail** (2026-10-18, desktop widths): the matter's folders and files, current file's folder chain open and highlighted, filter by name, big folders show 200 files then "Show all", matters over 3,000 files list only the current folder and link other folders to the Documents tab (`getViewerFileTree`); collapsible, remembered per browser.
  - Chrome: breadcrumb back to Documents preserving `?folder=`, category/status chips, size + uploader + date, Download, prev/next through the folder ordered by name (server-resolved).
- [x] **Document storage: production Vercel Blob** (2026-07-07, ADR-015; private since 2026-10-16, ADR-018) — `src/lib/file-storage.ts` is a facade over `local` (`./uploads/`, dev default) and `vercel-blob` drivers (`src/lib/storage/`); `BLOB_READ_WRITE_TOKEN` selects blob, `STORAGE_DRIVER` overrides. One key scheme (`{rand16}__{name}`) everywhere; blob rows store the full blob URL in `Document.fileUrl`; reads/deletes dispatch on key shape so driver switches never strand old rows. Prod uploads are client-direct (`/api/documents/upload/blob`: `handleUpload` token route checks session + `documents.upload` + matter/folder scoping + extension-derived allowed types/size caps; Vercel's signed callback creates the Document row); bytes never transit our functions (ADR-034, clears the ~4.5 MB serverless body cap). The busboy streaming route stays for local dev (blob's callback cannot reach localhost) and 501s under the blob driver. Documents and cached email attachments live in a PRIVATE store: a stored URL fetches nothing (403); download routes 302 to a presigned GET scoped to one file (15 min; 6 h for audio/video so long recordings keep seeking). Server-side reads (docx/text/CSV previews, filing an attachment to a matter) use an authenticated `get()` via `readStoredFile`.
- [x] **Document metadata edit** (rename, re-categorize after upload) — `documents.edit` (migration-granted to roles holding `documents.upload`). `updateDocumentMetadata` in `src/app/actions/documents.ts`: wall via `assertChildMatterAccess`, name trimmed 1-255, category from `DOCUMENT_CATEGORIES`, no-op when unchanged, one activity row ("Renamed document" / "Changed document category" / "Edited document details"). "Edit details" dialog (`edit-document-dialog.tsx`) from the row kebab and the viewer header; metadata only, never bytes (ADR-034).
