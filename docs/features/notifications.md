# Notifications

In-app notifications are complete: bell, feed page, triggers, and an hourly deadline sweep. Email / SMS / push delivery and per-matter preferences are not built.
Related: [ADR-033](../decisions/033-error-boundaries-use-retry-the-notification-bell.md), [deadlines-and-tasks.md](deadlines-and-tasks.md), [PERMISSIONS.md](../PERMISSIONS.md)

## Shipped
- [x] **v1 in-app** — `Notification` model (per-user, per-event row, `readAt`, optional matter scope). Writers `createNotification` / `createNotifications` (fan-out + dedup) in `src/lib/notifications.ts` mirror the `logActivity` fire-and-forget contract. Topbar `NotificationBell` self-fetches every 60 s and on open (via GET, ADR-033). Mark-one-read on row click; mark-all-read in the header. Actions scope per user so a guessed id cannot flip another user's row. Identity-scoped: no permission key.
- [x] **v2 in-app complete** — `/notifications` feed (newest-first, 50/page via `?page=`, optimistic mark-read, linked from the bell's "View all"); shared `NOTIFICATION_TYPE_META` (`src/lib/notification-type-meta.ts`) keys icon/tone so bell and feed render identically.
- [x] **Triggers** — matter team add (notifies the new member); invoice payment recorded (matter team minus actor); task assignment; settlement approval steps (`setApprovalStepStatus`: approve fans out to the active team minus actor naming the next pending step; reject pings the matter lead(s); repeats/resets silent); deadline sweep.
- [x] **Task owner picker** (2026-07-07) — AssigneeSelect (Unassigned + active users, initials chip) on the task composer and edit dialog. Create/update/reassign all funnel through `notifyTaskAssigned` (`src/lib/task-assignment.ts`) with the actor-exclusion rule, so assigning someone else pings them even at create time (sibling task captures still self-assign, silent by construction). Triggers: `updateTask` and `createTaskWithCaptures`.
- [x] **Deadline sweep** (`src/lib/notification-sweeps.ts`) — 7-day and 1-day `deadline_approaching`, a "Deadline due today" notice, and a one-time `deadline_overdue` flip that fires only after the due day ENDS, both in the recipient's profile zone. Recipients: the owner, or the active team when ownerless. Idempotent via (userId, type, link); link format `...?deadline=<id>&due=<7d|1d|today|overdue>&on=<YYYY-MM-DD>`. Runs under a Postgres advisory lock. The rollout produced one duplicate notice per in-window bucket. Also invoked fire-and-forget from the dashboard behind an in-memory once-per-hour-per-instance throttle.
- [x] **Scheduling** (2026-10-16) — `vercel.json` crons run `/api/notification-sweep` hourly and `/api/email-sync` (mail + calendar pull) every 5 minutes. `GET /api/notification-sweep` is a sanctioned system-endpoint exception to "mutations are server actions" (CRON_SECRET bearer, fail-closed). `CRON_SECRET` is set in production; the auth proxy exempts both paths (they self-authenticate); `src/vercel-config.test.ts` pins the wiring.
