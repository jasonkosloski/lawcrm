# Intake (leads)

Lead queue, new-intake form, lead detail with Overview / Time / Notes / Tasks / Events / Documents / Records / Communication tabs, conflict checks, decline and lead-to-matter conversion are shipped. Everything created on a lead carries forward to the matter on conversion.
Related: [ADR-044](../decisions/044-intake-notes-share-the-note-table-scoped.md), [ADR-045](../decisions/045-intake-tasks-and-events-reuse-task-and.md), [ADR-046](../decisions/046-intake-documents-share-document-and-documentfolder-scoped.md), [ADR-019](../decisions/019-deadline-rules-task-lists-as-firm-libraries.md), [ADR-026](../decisions/026-conflict-matcher-scope-own-contact-exclusion-inactive.md), [records-requests.md](records-requests.md)

Lists every open lead (a notice appears past the 1,000-lead safety bound); closed history pages behind them (`?page=N`, 200 per page); statute column is a live countdown; Decline / Convert buttons depend on role.
- [x] **New intake form (`/intake/new`)** (2026-10-17) — `createLead` gated by `intake.create` (queue "New intake" button and the Cmd+K row). Person: type-ahead over active, unmerged contacts links a repeat caller; else a typed email matching an active contact (case-insensitive) links to it (form says so before save); else a new `client` contact (+ primary ContactPhone). Inquiry: source + detail, summary, incident date (date-only, ADR-012), location, injuries, prior counsel. Conflict matcher runs on save and the result is stored; activity-logged; lands on the lead page.
- [x] **Lead detail — v1 page and tabs** — case summary, assessment bars (liability + damages), contact card, intake meta, conflict-check card, converted-matter link. Communication tab is contact-scoped (joined `Lead.contact`, picks up Contact edits) and shows email threads plus SMS/call/voicemail.
- [x] **Lead -> Contact integration** — every lead hangs off a first-class Contact via `Lead.contactId`; conversion reuses it.
- [x] **Conversion conflict gate** (2026-10-18) — `convertLeadToMatter` re-runs the matcher at submit: a live conflict refuses (only a recorded override gets through), possible conflicts need a review tick in the dialog, and the outcome is on the matter timeline. - [x] **Conflict check automation (v1)** — pure matcher `src/lib/conflict-check.ts`. Email match: conflict if the contact appears as opposing-side, else warn. Severity clear/warn/conflict. `runLeadConflictCheck` persists status + timestamp; `overrideLeadConflictCheck` flips warn/conflict to "override" with a 5+ char justification. Keys `intake.conflict_check.run/override`; audit-logged. The lead's own Contact never matches itself; deactivated contacts still parties on active matters stay in the hard (opposing) tier; merged-away contacts are excluded. Audit titles name the lead.
- [x] **Decline lead** — topbar action with optional internal reason; `Lead.stage` = "declined", leaves the active queue. Conditional (`stage notIn converted, declined`): a second decline changes nothing and writes no second audit row.
- [x] **Convert lead to matter — v1 + integrity (W8b)** — topbar action with practice area, initial stage, matter name, fee structure. ## Notes
- Scope pattern: lead-scoped records use "exactly one of (matterId, leadId)" (tasks/events: at most one) and a `RecordScope`; revalidation via `scopePaths(scope, ...)`. All lead tabs refuse writes on converted leads and carry their records forward in `convertLeadToMatter`.
- Template generation on a lead: `resolveMergeContext` accepts a lead; `client.*` comes from the lead's contact, `matter.*` fields resolve to null and render as the engine's visible "[… — not on file]" placeholder (reported missing); `firm.*`, `user.*`, `today` unchanged.
- On lead documents, matter-only links (evidence links on flags) are hidden. Every reader of `Document.matterId` / `DocumentFolder.matterId` must tolerate null (search, `CHILD_RESOLVERS` in `matter-access.ts`, email-attachment and copy paths, flagged-moment queries).
- Email attachments, "Copy to…", flags and delete reference-counting work unchanged on lead documents; copy targets must be in the same scope.
- `matter-access-guards.test.ts` allowlist entries only where an action genuinely has no matter.
