# Communication — Email (Gmail)

Unified inbox at `/communication` (route reserved so SMS plugs in without a rename). Real Gmail syncs in and goes out (rich-text, from the user's own mailbox), with read/star/archive writeback, attachments on demand, and file-to-matter. Originally the P0 "Gmail OAuth + email send / reply / file-to-matter" blocker — all phases shipped; only follow-ups remain. Phone/SMS/voicemail lives in [communication-calls.md](communication-calls.md).
Related: [ADR-011](../decisions/011-oauth-tokens-encrypt-at-rest-via-a.md), [ADR-023](../decisions/023-google-sync-skips-only-deterministic-failures-catch.md), [ADR-043](../decisions/043-email-attachments-become-documents-copy-to-makes.md), [ADR-042](../decisions/042-excel-and-email-convert-on-the-server.md), [PERMISSIONS.md](../PERMISSIONS.md), [google-calendar-sync.md](google-calendar-sync.md)

## Shipped
- [x] **Gmail OAuth connect** — Per-user: any firm member connects THEIR OWN mailbox(es) at /settings/integrations; creds only from `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, redirect URI derived from request origin / `AUTH_URL`. Routes `/api/integrations/google/{connect,callback}` (sanctioned route-handler exception) with signed state + httpOnly nonce cookie CSRF gate; `access_type=offline` + `prompt=consent` guarantees a refresh token. Callback upserts `EmailAccount` per (userId, emailAddress); tokens encrypted at rest (ADR-011) with expiry inside the encrypted column as a `{token, expiresAt}` envelope. Connect refuses grants missing `gmail.modify`/`gmail.send`; connect/disconnect audited as `auth` rows. `disconnectEmailAccount` is owner-only (no admin override; the admin lever is deactivating the user), best-effort Google revoke, clears tokens, KEEPS threads (firm records). Key files: `src/lib/google/gmail-client.ts` (`getGmailAccessToken` refreshes on expiry, persists rotation, flips account to `error`+`syncError` on `invalid_grant`; `gmailFetch` wraps gmail/v1 with one refresh-and-retry on 401).
- [x] **Sync engine** — `src/lib/google/gmail-sync.ts`. Incremental via `users/me/history` from stored `historyId` (affected threads refetched `format=full`; 404 cursor-expired falls back to full resync). First import is capped at newest **200 threads / 90 days** (`FULL_SYNC_MAX_THREADS` / `FULL_SYNC_MAX_AGE_DAYS`) — a product choice, not a sync error. Idempotent upserts update ONLY provider-owned columns; app-owned state survives every resync (`matterId` filing, `followUpAt`, spawned notes/tasks/deadlines, `isPrivileged`, app labels, downloaded attachment `fileUrl`s). Gmail user labels land in `custom:*` (reconciled each pass; system + `CATEGORY_*` filtered; they feed `isRead`/`isStarred`/`isArchived`). Bodies: MIME walk prefers text/html → escaped text/plain → snippet; in-house RFC 5322 / RFC 2047 parsing (`gmail-message-parse.ts`); non-UTF-8 decoded by part charset. **Every body is sanitized at WRITE time** (email profile in `src/lib/sanitize-html.ts`: scripts/iframes/forms/handlers stripped, safe inline-style subset kept, REMOTE IMAGES BLOCKED with visible "[image blocked]", `data:` images render). Triggers: `syncMyEmailAccounts()` ("Sync now" in the Communication topbar), throttled page-load kick (`maybeKickEmailSync`, in-memory 5 min/user/instance), headless `GET /api/email-sync` (CRON_SECRET bearer, fail-closed, constant-time check, all users, per-account failure isolation).
- [x] **Sync integrity (W6a, ADR-023)** — DRAFT messages never stored; NUL bytes stripped; deterministic-data failures skip the thread (ids logged) while connectivity/transient DB errors abort the pass with cursor untouched (several threads failing also aborts); skipped poison threads surface in `syncError` ("N thread(s) could not be imported"). Expired-history fallback for a previously-synced account is an uncapped catch-up since `lastSyncAt − 1d` (safety cap `CATCHUP_MAX_THREADS` = 1000; hitting it does NOT advance cursor/`lastSyncAt`, noted in `syncError`; current threads skipped via `format=minimal` so repeat passes reach the older gap). Incremental sync never imports an unknown thread older than the oldest local one. Deactivated users' accounts don't sync (reactivation resumes). SPAM/TRASH-only threads not imported (local copies kept, read + archived). Per-account sync claim makes concurrent Sync now / cron / page-kick skip (stale after 10 min). Failure semantics: `GmailAuthError` → account `error`, stop until reconnect; transients restore status and record `syncError` (cleared on success). Read/archive writeback touches only message ids the CRM has synced (`messages/batchModify`, per-message fallback on stale id).
- [x] **Paged thread lists** — the inbox, the messages view and a matter's Communication tab page by `?page=N` (100 per page, exact totals; opening a thread keeps the page). The lead tab's address match can't page cheaply (verification pass), so it caps at 500 candidates and says so.
- [x] **Send / reply** — Compose button in the inbox list header (`ComposeEmailLauncher`; hidden without `communication.send_email`; "Connect Gmail" link when no account; From picker only with several accounts) + Reply / Reply-all (`ReplySection`) in the thread reader, working in the full inbox AND embedded matter/intake readers. Every send goes from the CURRENT USER's own `EmailAccount` (ownership in the action WHERE clause). `src/app/actions/email-send.ts` (`sendEmail`, `replyToThread`, both gated `communication.send_email`) build multipart/alternative MIME via client-safe `src/lib/google/mime.ts` (RFC 2047, header-injection stripping, 76-col base64) and POST `users/me/messages/send`. Reply recipients from the last INBOUND message (reply → its From; reply-all → From+To+Cc minus own address, case-insensitive dedupe), "Re:" without stacking, edit-recipients override. Replies pin Gmail `threadId` (no fabricated In-Reply-To). Sent message + thread upsert locally on the sync engine's unique keys so the next sync converges; filed threads log "Email sent"/"Email reply sent". Failures return `{ok:false,error}` and composers PRESERVE the draft; exception: once Gmail accepted the send, a failed local save returns `ok:true` with a warning and the draft clears. Cancel/Esc blocked mid-send; Enter in single-line fields doesn't send. Limits: 50 recipients/field, 100 total, subject 998 chars, body 1,000,000 chars.
- [x] **Rich-text compose** — Compose + reply use the shared Tiptap `src/components/shared/rich-text-editor.tsx`, loaded through `rich-text-editor-lazy.tsx` (`next/dynamic`, client-only) so Tiptap ships only with a mounted composer (`NoteEditor` is a re-export alias of the lazy one). Toolbar matches notes (heading, bold, italic, strike, code, lists, blockquote). `bodyHtml` is sanitized SERVER-SIDE in `email-send.ts` via `sanitizeUserHtml` (note profile — stricter than the inbound email profile, so a hostile client can't smuggle styles/images into mail wearing our From); `bodyText` via `htmlToText()` (`src/lib/html-to-text.ts`). Locally stored sent body is the sanitized wire HTML; snippets stay plain text. No automatic signature.
- [x] **Attachments — bytes on demand + file to matter** — Sync stores metadata-only rows (`fileUrl: "gmail:<id>"`). `GET /api/email-attachments/[id]/download` is scoped attachment → message → thread → account to the CURRENT user's mailbox (matches the owner-scoped `getThreadById` model). First hit fetches from Gmail, caches via `storeFile`, flips `fileUrl` to a storage key exactly once (conditional updateMany; concurrent losers adopt the winner's copy). Disconnected account + uncached bytes → 409 with reconnect message. Serving mirrors the documents route: shared inline allowlist `src/lib/inline-safe-types.ts` (sender-declared contentType is attacker-controlled), nosniff, CSP sandbox on forced attachments, single-range 206, blob keys 302. **File to matter:** `fileAttachmentToMatter` (`documents.upload`, `src/app/actions/email-attachments.ts` + `src/lib/email-attachments.ts`) writes an independent COPY under its own storage key as `category: "correspondence"` / `source: "email"`; contentType re-derived from filename extension. Re-filing to the same matter no-ops (`alreadyFiled`, name+size heuristic); second matter = independent copy; activity-logged "Filed email attachment". UI: `AttachmentChips` — Download, View (inline-safe types only), "File to matter…" dialog (defaults to the thread's filing; per-matter folder picker via `listMatterFolders`). See ADR-043 for uploaded-email attachments as documents.
- [x] **Writeback + older-mail backfill** (2026-07-07) — `src/lib/google/gmail-writeback.ts`: in-app read/star/archive push label modifies to Gmail (`threads/{id}/modify`: UNREAD / STARRED / INBOX) so the provider doesn't revert CRM intent (the double-inbox fix). Local write ALWAYS commits first; `writebackGmailThread` never rejects (token-less accounts skip silently, `GmailAuthError` records reconnect signal on `syncError`, transients warn). If a writeback fails, the local flag holds only until Gmail next reports the thread, then Gmail's labels win. Echo-safe: sync derives flags from labels and never triggers writeback. Actions in `src/app/actions/email-thread-flags.ts` (`setEmailThreadStarred`, `toggleEmailThreadStar` legacy wrapper, `setEmailThreadArchived`; session-gated, mailbox-scoped; archive no-ops on same state); mark-read rides `markEmailThreadRead`. UI: hover/keyboard-reveal star + archive cluster (`ThreadRowActions`, sibling overlay, optimistic star) on inbox and embedded matter/lead lists; **Archived** mailbox view in the rail (`filter=archived`). **Backfill:** `backfillEmailAccount` / owner-scoped `backfillMyEmailAccount`; "Load older emails" per account on the integrations Gmail card (shows oldest-thread anchor date, imported count). Each click walks ONE window of up to `BACKFILL_MAX_THREADS` (200) threads strictly older than the oldest local thread (`q=before:<epoch s, rounded up>`), newest-first, already-local threads skipped without spending the cap; clicks stack. Stays out of the sync status machine (`historyId`/`lastSyncAt` untouched).
- [x] **Thread read tracking** — Opening a thread marks it read. `markEmailThreadRead` / `markMessengerThreadRead` in `src/app/actions/thread-read.ts`: session-gated (no catalog key — viewing-inherent), transactional flip of item flags + denormalized `MessengerThread.unreadCount` (heals drift), no-op + no revalidation if already read. Fired by invisible `MarkThreadRead` island in both readers.
- [x] **Matter detail — Communication tab** — Email threads filed via `EmailThread.matterId`; embeds the thread reader; Email | Phone channel toggle (phone side in [communication-calls.md](communication-calls.md)).

## Notes
- Email reads and mutations are owner-scoped: the inbox shows only the viewer's own mailbox; filing a thread to a matter (`setEmailThreadRecord`), create-from-email and log-time-on-email are owner-only.
- Unread filter, rail count and tab badge exclude archived threads; the pinned-matter drilldown lists archived threads (default filter all).
- Operations: `CRON_SECRET` required in production; Google Cloud project needs BOTH Gmail and Calendar APIs enabled.
